# R8.1：依据城市证据校订全景候选 V13

本批继续“文献平面—定位依据—城市分布—深化全景”的路线，将R7.1四节点核验用于新的首页候选图。实现版本为 `panorama-review-v13`，图像版本为 `panorama-candidate-v13`。研究窗口仍为516—528年；古代坐标与古岸几何新增均为0。

## 发布范围与审看

新增 `luoyang-panorama-v13.html`，提供V13与当前V12全幅切换、并排对照、逐项图面处理及证据链接、图像和依据下载。窄屏并排模式改为上下排列，图片始终按自然比例显示，标题、图注和控件放在画面外。无脚本时两幅图及全部证据依次展示。

沿用用户“重绘后先审看，再替换”的要求，新图的状态是 `candidate_for_review`，`homepage_replacement_approved=false`。两个正式首页入口继续展示 `panorama-approved-v12`，只在既有R7研究入口之后增加一条精确可逆的候选图链接。页面发布本身不宣告候选图获得首页使用批准。

## 证据与成图记录

最终改图说明取自 `research/panorama-r8/image-record.json`；记录需在实际查看成图后填写，不把生成提示词当作已经完成的画面事实。原V12图像身份、候选大小图的像素尺寸与SHA-256、实际使用的完整生成步骤及提示词、逐项观察、依据、实际处理与限制随发布保存。`source-audit.json` 是原件访问记录，`visual-audit.json` 是V12基线图面审查，`candidate-review.json` 是V13成图后的独立目检；三者在完成后作为各自原字节附件发布，不能用基线审查冒充最终候选审查。

可下载的审看数据完整保留这些记录。候选画面中的艺术细节不能回写为道路、墙体、桥头、古岸的考古坐标，也不能把仓窖数量转成同期地面建筑网格。

最终原PNG也列入来源指纹。构建核对实际原件、顶层记录及原图记录的SHA-256一致，并读取PNG的IHDR及其校验值确认实际宽高与原图、全幅WebP记录一致；最终成图核查必须指向同一原PNG。

## 既有版本保护

构建在R7之后追加本阶段。新阶段保存两份前版首页原文；删除唯一声明的候选入口必须逐字节还原R7首页。V12及R7的既有验证仅先撤销这个精确新增项，再执行原来的首页还原判据。未知改动或篡改链接仍会失败。

R7图面、CSV、JSON、离线ZIP、V12图像和批准元数据全部列入新阶段保护清单。根 `.nojekyll` 保留构建字节合同，实际公开文件继续逐项HTTPS与哈希校验。

## 验收

数据检查覆盖候选状态、图像指纹与尺寸、来源记录逐值保留、前版资源保护及首页精确还原。浏览器检查在桌面和手机验证两个首页入口、候选状态、全幅比例、键盘切换、并排阅读、URL恢复、证据锚点、真实下载与无脚本阅读。

最终发布仍以主分支 `build → deploy → verify-live` 三阶段成功、正式站来源核对和 #47／#52 的长期交接记录为准。本说明不代替实际运行结果。
