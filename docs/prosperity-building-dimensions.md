# 盛时建筑平面尺度与体块依据

核读日期：2026-11-14。作为盛时工作层的后续建模依据保存。范围限定为现有`research/prosperity-v1/geographic-evidence.json`的尺度字段、同一申遗附表与相邻考古图，以及已取得的《洛阳伽蓝记》电子正文，没有扩展为新的全城建筑史调查。

## 可立即执行的结论

下一版可以把若干抽象图符升级为**有表列尺度约束的遗址基座片、院界框和分段墙带**。这一步可改善宫城、殿基、门基与寺院之间的尺度关系；目前没有足够依据把这些对象全部升级为有确定米制高度、屋顶和柱网的盛时建筑模型。

当前7组`source_dimensions_m`数值均能在申遗附表对应条目中核到。新增可利用的同表信息包括宫墙分段宽度、永宁南门与西门尺寸、太极殿夯土深度。**深度、残高、上部建筑高度必须分字段**：太极约6m是夯土深度；永宁塔基2.2m、南门1.2m是遗存高度，均不能充作盛时完整建筑高。

本说明中的“已核平面尺寸”只表示已在机构来源表中实际对到数值、方向和对象，不等于本项目重新测量，也不保证所述遗存在516—528每一年都有同样的上部构件。

## 历史高度只作为文献说法保留

### 永宁九层木塔

[周本卷一](https://deerpark.app/cbeta/B0077/1)，B12n0077_p0045a06—09：

> 中有九層浮圖一所，架木為之，舉高九十丈。……上有金剎，復高十丈；合去地一千尺。

[范本卷一](https://deerpark.app/cbeta/B0078/1)，B12n0078_p0341a11—15可见相应古文。保留九层、木构与原文数量，但本轮没有解决尺度制、叙述性质及其他史籍数值异说，因此`historical_height_m`必须为空。九层也不意味着可任意指定九段等高楼层并宣称为复原。

### 永宁寺门楼

周本p0048a13—15记南门楼三重、去地二十丈；周本作“通三閣道”，范本p0343a10—12作“通三道”。二者是同书整理本的取字问题，不形成独立见证。

周本p0049a15—p0050a01记东西两门楼两重；p0050a01—02明确北门一道、不施屋。可用于限制示意类型，但没有为东、西、北门补足米制尺寸。不能由“亦皆如之”把南门二十丈机械传给其他门楼。

### 宫阊阖与太极殿

既有B4:NG02中的城门总叙“去地百尺”不能直接套给宫城阊阖门。宫前门与城西同名门原本就分实体。太极殿此次附表没有建筑原高；“浮圖北有佛殿一所，形如太極殿”（周p0047a04）是形似语，不能证明两殿的大小、屋顶和柱网相同。

## 实现顺序与字段约束

1. **先完成三个尺度片：**M02阊阖门基、M03太极殿、M05塔基。坐标采用已有来源图节点，平面尺寸采用表值，位置概化与尺度精细度分开显示。
2. **再加入宫墙带与寺院框：**M01与M04。证据线不被新模板覆写；宫城北缘仍不作为墙，永宁寺院界与表值的拟合仍为工作判断。
3. **把门基列为局部建模任务：**M06先不落点；M07须先完成图40中实测线与复原线的分层提取。附图37可支持阊阖三通道与东西阙平面的后续提取，但上部高度继续为空。
4. **M08保持关系注记。**本轮没有足够依据扩大为有尺度的屋顶建筑群。

建议后续模型至少分别存储：

```json
{
  "plan_dimension_source": "附表编号与页码",
  "position_basis": "来源图概略中心或证据线",
  "historical_height_m": null,
  "surviving_height_m": null,
  "below_surface_or_fill_depth_m": null,
  "roof_model": null,
  "display_extrusion_is_historical_height": false
}
```

用于看清平面的绘图厚度应采用独立的屏幕／场景参数，不写进`historical_height_m`，不标成古代米高。画布零平面也不是古代地表高程。若后续增加纯解释性的高塔轮廓，应作为另有声明的概念层，不能替换本轮证据体块。

来源图定位仍沿用西安1980框架。既有100m工作显示容差不是实测精度或统计置信区间；一个台基尺寸记到0.1m，不使其概略中心坐标获得0.1m精度。该框架也不能直接与WGS84地形叠加而省略基准转换。

## 对现有其他尺度字段的核查

金墉丙城约310×240m在PDF1927可核，但只代表丙城范围；表中该行没有明确长宽方向，不能扩成完整金墉三城。铜驼残段1650m、宽40—65m在PDF1930可核；保留范围式路带，不取一个最大宽度沿全轴铺满，也不由残段端点补出宣阳门。

以上两项不扩入本轮核心8组体块清单，避免范围蔓延。所有待证项已写入伴随JSON。

## 交付与核查边界

伴随文件`building-dimensions.json`包含8组实施对象、7组既有尺度字段核对、逐项页码、原高／残高／夯土深度分离、可实施范围与禁止推断。几何、建筑高度和屋顶未由这份核读清单自动生成。本轮没有新建古址坐标，没有把现代地面当古地面，没有选择任何屋顶类型，也没有给未知建筑填入假定米制高度。
