# 盛时洛阳地理骨架：来源图配准与使用边界

研究版本：`prosperity-geography-v1.0`。日期：2026-11-14。数据：`research/prosperity-v1/geographic-evidence.json`。

## 本版实际取得的结果

已从公开的申遗原件中读到带经纬刻度、坐标基准与底图年代的汉魏洛阳城专属地图，并提取30项可重算的地理要素，包括内城遗存墙线、宫城三面墙、金墉丙城局部、永宁寺与塔基、宫城阊阖门、太极殿、部分城门和道路。由此可建立独立于旧文献平面图的第一版城市地理骨架。

这些是**来源图中遗址位置的派生坐标**，不是本项目开展的考古测量，也不是现场核验控制点。此前“未建立地面核验控制点”的限制仍然成立；现在新增的是可检查原图、坐标网、变换与顶点的地理定位依据。旧有文献地图实体、示意几何与封存版本不在本版改动范围内。

数据坐标采用 **1980西安坐标系，EPSG:4610**。JSON中的几何坐标统一以 `[经度, 纬度]` 存储，不能当作WGS84或RFC7946 GeoJSON直接叠加现代网络底图。

## 二、坐标、网格与配准

图06a明确注明底图为**1997年航摄、1999年实测，1980西安坐标系、1985国家高程基准**。经度标线为112°34′、36′、38′、40′E，纬度标线为34°40′、42′、44′、46′N。图上没有明确印出投影名称和分带号，因此本版不为原图指定未经证明的高斯—克吕格带号。

EPSG名称对应由[Open Geospatial Consortium的EPSG:4610条目](https://opengeospatial.github.io/ontology-crs/data/def/crs/EPSG/0/4610/index.html)核对：Xian 1980，IAG 1975椭球，长半轴6,378,140 m，反扁率298.257。原规范轴顺序为纬度、经度；本项目几何存储顺序已明确改为经度、纬度，以免渲染时颠倒。没有执行到WGS84或CGCS2000的转换。

### 配准方法

1. 直接读取PDF图06a的矢量刻度，不以OCR文字中心或手点标签代替刻度。
2. 顶、底各取4个经度刻度，左、右各取4个纬度刻度，共16个**单轴约束**。这些不是16个地面控制点；每个边缘刻度只提供其已标出的经度或纬度。
3. 分别用8个约束最小二乘拟合：`经度 = a*x + b*y + c`、`纬度 = d*x + e*y + f`。`x,y`采用PDF左上角原点的point单位，y向下。
4. 从同一页提取选定遗存线的PDF矢量顶点；曲线按每段8个等参数区间采样。各要素保留drawing index、seqno、PDF坐标及1800像素宽整页渲染下的像素坐标。
5. 将每条几何转换到EPSG:4610经纬度。元数据保存全部控制约束、拟合系数和残差，可独立重算。

整页原始尺寸为595.276 × 841.890 PDF point。核读整页图宽1800像素、高2546像素；对应比例因子为 `1800 / 595.276`。地形底图本身是811 × 778像素的嵌入栅格，叠加其上的古迹线、图例、标注与经纬刻度包含独立矢量。**放大页面不会增加底图的原始分辨率。**

图内刻度拟合的均方根残差，换算到34.73°N附近，约为经向5.88 m、纬向0.83 m。这只说明变换对印刷网格的复现程度，不证明某座城门或寺院拥有这一地面精度。原测图误差、古迹标绘误差、地图综合、基准转换和现场同名异物问题不由残差解决。

### 使用精度

核心位置采用100 m工作展示容差，外郭范围250 m，手工概略采样的现代洛水主槽150 m。它们是本项目保守的显示设置，**不是原件发布的精度指标、绝对误差估计或统计置信区间**。绝对地面误差仍填空值，现场核验GCP数仍为0。坐标的内部小数位服务于重算，不能在面向用户的文字中暗示亚米或米级考古定位。

## 四、年代和尺度的交叉检查

遗址总图是一张多时期遗存图，不能只见到某处建筑符号就把它放进516—528的盛时运行图。附表核读后，本版排除了以下默认运行对象：雍门Cnm-2在该表只标东汉至魏晋；两处太仓武库Jn-3.1/3.2及东部冶铁Jn-4.2标东汉。保留这些来源记录供后续比较，但不据其位置假定北魏仍在运行。

几项对建模有用的原件表值已经独立存入数据：

| 遗存 | 原件记载的尺寸 | 页码 |
|---|---|---|
| 宫墙 | 西墙遗存1398 m，东墙遗存1284 m，南墙660 m | PDF1926，附录印刷1 |
| 金墉丙城 | 约310 × 240 m | PDF1927，附录印刷2 |
| 宫城阊阖门门基 | 东西44.5 m、南北24.4 m | PDF1927，附录印刷2 |
| 铜驼道路残段 | 长1650 m，宽40—65 m | PDF1930，附录印刷5 |

小建筑和门使用的是综合、放大的地图符号。例如图06a永宁塔基符号的图上尺寸明显大于附表38.2 m的实际表值；围墙横宽也与附表212 m不完全相符。因此本版以它们的中心和关系定位，以独立表值约束尺度，绝不把图符直接拉伸成“实测建筑”。塔基残高2.2 m亦不等于北魏塔高。

## 五、地形线本版的具体界限

本版突破的是**遗址地理位置依据**，尚未取得北魏地形模型。图06a的底图年代与坐标/高程基准可以明确追溯；但是现有嵌入栅格分辨率不足，北部山地虽可见起伏线条，却不能稳定辨读等高数值。因此没有创建伪等高线、伪高程点或用现代DSM填充古地面。

现代洛水参考线只是手工概略采样的蓝色主槽中东段中线；经视觉核对，西侧分汊与模糊河岸未追踪，河宽和细小支槽亦未提取。它可帮助用户理解遗址和现地地貌的大致关系，必须单独显示“1997/1999地理参照”时层。北魏洛水、南城墙被河流影响的范围、桥位和宣阳门仍需古河道与独立遗址资料。

## 六、接入分布图和全景的规则

- 用本版EPSG:4610数据生成独立的本地米制布局。若与WGS84 DSM、卫星底图或GCJ-02地图叠加，必须先另行取得适用转换与独立检查，不能改写CRS标签或使用零转换冒充验证。
- 内城南墙、宣阳门、完整金墉和古洛水保持缺口；显示范围不等于实证轮廓。
- 文献实体只有在名称、同一性、时期、空间关系都可核对后，才与来源图要素建立对应，不按同名自动合并。
- 城市全景采用同一宫城、寺院、道路空间骨架。上部建筑形制、建筑高度、居民密度、天际线和季节仍是另一组复原参数，不能借位置已有依据就宣称这些也已证实。
- 这一骨架可以让全景的尺度来自真实城市范围和主次关系：城域与道路控制远近，宫城和寺院提供节点；宏伟感不必依赖将每个建筑放大或机械铺满整齐屋顶。

## 七、仍需补的最小证据

1. 可独立核验的宣阳门、南墙及北魏河槽范围；未得证前不提供点坐标。
2. 宫城北部与完整金墉三城的另一套可定位原图，用来检查2012管理图的时效与截取范围。
3. 具备明确位置、年代与基准的地形/古河道资料，区分现代耕作面、河漫滩变化和六世纪古地面。
4. 足以验证1980西安到现代底图坐标转换的区域参数及独立控制，不以“图上看起来接近”作为通过条件。

以上缺口不阻止本版来源图骨架进入可见研究布局，但限制其措辞与显示方式：应称“有原图依据的地理布局研究版”，不称“北魏真实地形和所有建筑精确复原已完成”。

## 八、实体绑定与本版校验

已核对13条feature到既有实体的绑定。宫城阊阖门只连`ic_changhe_palace`；永宁寺两项以组成部分身份连`ic_yongning`；千秋、建春、大夏、广莫、西阳、东阳、清/青阳、西明按各自门实体连接。金墉两项连`ic_jinyong`时明确限定为丙城部分参照，不能替换全城范围。清/青阳对应使用旧实体已登记的别称，不另造门。

太极殿和云龙门没有强绑到不相符的旧实体。宫城范围与道路起讫尚未完全等同的对象只列相关/候选实体。现代洛水、邙山区域标注也只列跨时层相关ID，不直接替换古代实体几何。

`geo-palace-layout-envelope.rendering`明确规定`fill=true`、`stroke=false`，其可见实证边线由`geo-palace-walls`另绘。数据契约测试不能替代前端检查；接入后还需确认整圈polygon不会被通用CSS或渲染函数意外描边。

新增`tests/test_prosperity_geography.py`的7项检查覆盖：基准/轴序、刻度残差与地面精度的区分、源顶点重算、现代地形时层、缺失南墙与宣阳门、宫城推定范围无实证描边、混合遗存年代及同名门分离。独立运行已通过。另已将提取后的核心墙线、门、道路与原图视觉核对；现代河道西侧模糊段据此删去。
