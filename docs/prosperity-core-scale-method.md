# 核心建筑定尺平面：定位与朝向方法

研究数据版本：`prosperity-core-scale-v2.0`，2026-11-14。机器可读规则见 [core-scale-basis.json](../research/prosperity-v2/core-scale-basis.json)。

## 本版采用的结果

本版可以在来源图既有位置上增加三项有米制依据的平面参考：宫城阊阖门基 44.5×24.4 米、太极殿遗址约 100×60 米、永宁寺地上塔基遗存约 38.2 米方。三者的尺寸、位置和朝向分别说明，矩形均称“尺度片”，不称已经逐边配准的发掘轮廓。

永宁寺 301×212 米院界继续作为**独立尺度比较模板**。固定尺寸与管理图三面墙的拟合已实际计算，但未获采用；它既不能替换现有证据墙，也不能以塔心为院心放入城市地图。

所有平面和鸟瞰共用同一米制几何。古代地面高程、建筑高度与屋顶仍为空；图面阅读厚度如有需要，只能是另设的屏幕像素参数。

## 工作朝向明确给值，实测朝向仍为空

宫城阊阖局部图（PDF 1962）有北箭头和 20 米比例尺；塔基局部图（PDF 1966）有北箭头和 5 米比例尺。它们提供图内定向线索，但没有坐标网，尚未与城市图形成独立的共同控制点和角度标定。塔基图的北箭头略向图面左上，不能把扫描图竖直方向默写成真北。

PDF 1965 上方寺院总图未见可读北箭头；下方西门局部图的“北”指向图面右侧，只适用于该局部图，不能移用到上方总图。图 02（PDF 3453）Fig. 4 英文标题为 Helv Gate，而图形与 1962 的宫城阊阖图高度相似；本版不以这个有冲突的标题另行绑定实体，宫城阊阖依据明确的 Cgm-3 表和 1962 局部图。

为使三个尺度片与来源骨架协调显示，本版使用两组明确标注的工作角：

- 阊阖与太极共用两个来源点的连线：东向差 11.307 米、北向差 573.771 米，工作北轴偏向局部东侧约 **1.129°**。它表示图上两点关系，不称古建筑实测中轴。
- 永宁塔基使用三面图示寺墙的共同正交工作轴，约 **0.914°**。方形塔基采用此角仅为显示对齐，既不证明塔基实测方位，也不表示寺院院框拟合已经采用。

三个模板均写 `orientation_verified:false`、`measured_orientation_angle_deg:null`，不存在“未知角度默填为已测北向”的处理。

数据中的角度约定为：局部坐标 X 向东、Y 向北；北轴从 +Y 向 +X 顺时针转角 θ。令 `east_axis=(cosθ,−sinθ)`、`north_axis=(sinθ,cosθ)`。矩形顶点为锚点加 `u×east_axis+v×north_axis`，其中 `u=±东西尺寸/2`、`v=±南北尺寸/2`。平面图、鸟瞰及下载文件须使用同一组顶点。

## 永宁院界的实际拟合

### 可用观测与算法

管理图可读寺墙只有西、南、东三侧，北侧没有可靠线段。P1 已保存的虚线各段仍保持原样。本版仅在副本上量算，不移动、拉伸或补齐 P1 墙线。

为避免源图虚线长短和顶点数量左右拟合，各墙内按实际描线长度作连续权重，西、南、东三面墙等权。南西、南东转角的折线分别拆给相应墙边，不把同一转角的两种方向混为一条直线。JSON 保存全部零起算线段索引，允许从 P1 重算。

先利用三面墙各自的线内方差求共同正交工作方向，随后固定模板东西 212 米、南北 301 米，只调整平移：东西边关于两侧线的均值对称，南边对齐南墙均值。301 米在这里决定模板中心距南边 150.5 米和假定北边；没有北墙观测参与验证。

### 结果与不采用的原因

| 检查量 | 结果 | 含义 |
|---|---:|---|
| 管理图三墙的共同工作角 | 0.914° | 来源图线的方向，非建筑实测角度 |
| 两侧来源墙的间距 | 264.889 米 | 比表列 212 米宽 52.889 米，约多 24.95% |
| 西墙对固定模板的法向 RMS | 26.447 米 | 模板与来源线不合 |
| 南墙对固定模板的法向 RMS | 0.164 米 | 南边被用于平移定位，因此接近对齐 |
| 东墙对固定模板的法向 RMS | 26.445 米 | 与西侧近似对称的不合 |
| 三面墙等权 RMS | 21.593 米 | 模板拟合残差，非外部位置精度 |
| 原塔符中心与拟合院心间距 | 约 0.35 米 | 几乎重合，尽管塔心未作为拟合控制点 |

左右各约 26.4 米的残差不能用 P1 的 100 米展示设置消解：后者不是实测误差界，更不是模型验收标准。源图矢量本身很直，其方向拟合内部 RMS 约 0.263 米，同样不能说明地下遗迹有这个精度。

完整永宁院图在 PDF 3453 / 图 02 Fig. 2；PDF 1965 / 附录 40 的同图南部被扫描块遮挡。完整图上塔基明显位于院几何中心南侧。原件内嵌示意图为 294×392 像素；粗读墙框约为 `(76,84)–(239,306)`，塔符中心约 `(162,213)`，读数容差约 3 像素。塔心约在图内院高的 8% 处偏离几何中心向南。这个数值只检查图内关系，**不转换为已测米制塔院偏置或地理坐标**；图本身明确属于复原示意，不能用它为精确古院心背书。

固定 301 米长度从管理图南墙向北补框，却使院心几乎与塔符重合，与上述图内关系不一致。因此，当前图示三墙、塔符和表列院界尺度不能被一个简单刚性矩形同时满足。

另作的自由角度拟合会将工作角转到约 6.430°，等权 RMS 仅降至约 20.561 米。旋转吸收了部分宽度冲突，却偏离来源墙的自身方向约 5.5°，也未解决相对关系问题，故不采用。

## 程序消费与图面表现

`templates` 只含三项可放在来源锚点上的尺度片，三个 ID 为 `core-changhe`、`core-taiji`、`core-yongning-tower`。每项提供严格的 `dimensions_m:{east_west,north_south}`、原点、朝向和说明、未旋转局部轮廓及禁止推断内容。

`comparison_templates` 中的 212×301 米院界框没有地理锚点，`city_overlay_allowed:false`、`tower_position_in_template_m:null`。可把它与三尺度片用同一比例尺独立展示，但不要自行在框中心添塔。比较模板 0° 是横竖排版约定，不是历史地理朝向。

`courtyard_diagnostic` 提供网站比较图需要的平面字段：`measured_wall_spacing_m`、`table_width_m`、`table_length_m`、`fixed_template_rms_m`、`tower_to_template_center_m`，以及来源墙局部坐标、原塔点、诊断拟合中心和工作角。这里 `measured_wall_spacing_m` 仅指对来源图线的量算，不能在网页上简写成“实测院宽”。左右同尺度比较时，建议左图保留原三面墙和塔点，右图画独立表列尺度框；若展示拟合叠图，必须醒目标“诊断拟合，未采用”。

尺度片应与来源锚点同时可识别，并通过图例和线型区别于已描遗存墙线。默认图例为：“定尺片：表列遗存尺度；定位：来源图概略点；朝向：工作对齐，尚非建筑实测方位。”

## 仍需解决的具体工作

下一步能够提升可靠性的资料，是含可辨共同控制点、比例尺和明确北向的原始局部发掘平面，以及完整寺院的分期墙线。先解决局部图与城市图的中心及朝向配准，再考虑将精细门基、塔基轮廓替换矩形参考。现阶段不靠扩大图符、补对称院墙、填古代高度或复制屋顶来掩盖配准缺口。
