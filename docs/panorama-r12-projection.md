# R12.1：从共同平面到首页全景的透视布局底稿

本轮把 R11 已有地面几何送入**同一个可复算的平面透视变换**，供 V14 首页候选改图使用。第 1—6 节所述纯平面底稿约束占地、前后关系和构件从属，没有生成建筑高度、屋顶或完整院落。另加的计层绘图占位层见第 7 节；它的展示高度和屋顶不进入历史地面数据。底稿采用南望北的同方向虚拟视点，不宣称恢复了旧全景的真实相机，也不是古代遗址的实测配准。

## 1. 输入和保存范围

旧候选为 `research/city-spatial-r9/panorama-v13-r2-source.png`，原图 1672×941，SHA256 为 `b2bc1486c1e6a7461fcbafd7234b4e15365cc3f65d3f454eb20882818284ade4`。它只用于选择构图参考，不提供新的历史坐标。

历史空间输入直接调用 `tools/city_plan_r11_geometry.py::build_geometry()`，复用 R11 的 89 项来源／局部／尺度／对照几何：28 项来源骨架、33 项局部构件、4 个报告尺寸片和 24 项独立宫城概览。没有把文献候选位置签补成地块；R11 的全目录与未定位记录仍由原母图保存。

`research/panorama-r12/projection.json` 逐项保存原几何、来源引用、几何角色、共同矩阵、投影坐标和绘图可见性；`source_inputs_sha256` 固定全部引用输入、构图基图及生成脚本的身份。未修改 R11 输入、候选绑定或证据等级。

## 2. 一个共同变换，两个构图参照

工作画幅与旧图相同，为 1672×941。两个指定位置都是**地面附近的构图目标**，不是塔顶或屋脊，也不是经过核验的现场控制点。

| 来源对象 | R11 地面参照 | 图面构图目标 |
| --- | --- | --- |
| 永宁寺塔基来源图符 | 沿用 R11 已有候选锚点 | `(515, 430)` px |
| 阊阖门来源图符 | 沿用 R11 已有候选锚点 | `(650, 315)` px |

另固定整体横向比例参数 `a=0.38` 和远近参数 `g=0.00012`，并令东西向同一地面横行保持水平。由这两个目标解出其余四项系数，得到：

```text
H = [ 0.38   0.0383708090217182     424.9862599932897  ]
    [ 0.0   -0.08848822067306178    206.51863997840601 ]
    [ 0.0    0.00012                 1.0              ]

[u, v, w]ᵀ = H × [x_east_m, y_north_m, 1]ᵀ
pixel = [u/w, v/w]
```

全部对象都用这个矩阵，没有每座建筑的私有缩放、平移或旋转。逆矩阵及两构图参照的实际残差也保存在 JSON 中。矩阵只用于来源地面坐标到艺术画幅的转换，不能解释为投影后的历史位置更精确。

### 为什么没有强行锁住旧太极殿像素

旧全景的塔基、宫前入口、太极区域之间，纵向压缩和相对占地并不能同时满足本轮共同平面。若强行锁定全部旧像素，将需要不正常的远近关系或逐对象变形。

因此，太极区域旧图约 `(610,175)` 的地面构图参照仅记录为粗略目视读数，**没有参与求解**。R11 太极来源图符通过统一矩阵自然落到约 `(631,240)`。这说明新图需要调整宫城的深度安排，不能把这约 65 px 的画面差当成遗址的地理位移。

永宁寺新刊寺墙在本画幅的外接范围约为 `x459–565、y399–454`。这会比旧候选里的寺院占地明显缩小。若又把它单独放大塞回全城，就不再是共同坐标约束的全景，因此本底稿没有这样处理。

## 3. 永宁寺局部只作显示放大

带说明细图和清洁细图都使用同一地面透视，随后作 5.2 倍的统一显示放大与平移：

```text
detail_pixel = [5.2*u - 1830, 5.2*v - 1784]
```

细图不是另一套寺院布局。南门的源图长边约 45.7 m，塔座主体约 39 m；通过共同透视后，南门画面长边仍略大于塔座。南门约 45.7×19.0 m 是来源平面读数，不能要求最终透视像素宽深比等于 `45.7/19.0`。

23 项局部构件的身份继续区分：木塔地基大框不是塔身或塔院；四侧突出部分不是本轮新绘的踏步；东门只标一个点；佛殿仅为刊图框，不能据此声称完整殿身已考古确定。七段寺墙按原来源线段保留，没有从模式图补出北门、僧房、回廊和院内道路。

清洁导图不显示点符，避免图像编辑把东门小符号扩成一座已知门楼；带说明细图把这个点单列为“东门仅为图示标位”。两种表达都在 JSON 记录。

## 4. 不送入艺术编辑的对象

- 2013 宫城概览的 24 项几何仍保存在投影数据中，但不画入本轮清洁导图。其调查点、版筑范围和未知细分时相不能自动成为同一年地上殿宇。
- 外郭相关遗存范围线不生成连续城墙。
- 旧宫城显示包络不提供北侧闭合墙。
- 旧 06a 永宁寺残墙不与新刊寺院轮廓混成一座院落。
- 一般来源点符不提供建筑占地；地下线、开放连接走向与尺度片保持各自角色。

现有城市道路与墙段只按 R11 保存的线段画作浅色背景，缺口没有补连。古岸、桥头、宣阳门和完整城市南墙没有从此投影获得新依据。

## 6. 复算与本轮核对

从仓库根目录运行：

```bash
python tools/panorama_r12_projection.py
```

实际交付使用 Python 3.11、pyproj 3.7.2、CairoSVG 2.8.2、NumPy 2.2.6 和项目固定 Noto Sans CJK SC 字体环境。`--no-render` 可以仅重建 JSON 和 SVG。

已逐项核对 89 个源几何、863 个顶点：同一矩阵的独立标量回算最大数值差小于 `1e-9 px`，逆算最大数值差小于 `1e-7 m`。这些是浮点计算一致性指标，不是考古测量精度。全部输入文件哈希在生成前后保持不变；开放线没有补闭，受排除的来源角色没有进入艺术导图。四幅 PNG 均已实际查看，文字引线和地基／塔座区分可读。

已核验实地共同控制点仍为 0，新古代坐标、新古岸几何、建筑高度值均为 0。新生成的艺术候选还须单独检查其实际成图，不能因底稿准确就预先声称候选遵守了全部轮廓。

## 7. 九层塔与三层门的绘图占位层

`tools/panorama_r12_massing.py` 在冻结的共同地面投影上另画计层占位，帮助图像编辑保留九层塔和三层南门。层数沿用 `research/city-spatial-r9/panorama-candidate-review.json` 的 CRR01、CRR03 审查范围；它们不提供层高、收分、屋顶或金刹尺寸的考古测量依据。

第三坐标明确记为 `artistic_display_units_not_metres`。绘图扩展为：

```text
u = (H_row0 · [x,y,1]) / w
v = ((H_row1 · [x,y,1]) - z_display) / w
```

`z_display=0` 时严格回到同一地面 H。占位层的高度、身段收分、屋檐外扩和屋脊形状都只是可复算的绘图取值；没有写回 R11 输入、`projection.json` 或原来的清洁地面图。计层细图为了容纳塔身，使用 `detail_pixel=[5.2*u-1830, 5.2*v-1450]`，与第 3 节纯平面细图的纵向裁幅不同。这仍是同一组对象的统一显示放大，不能把放大图另贴入全城而改变寺院占地。

**佛殿和太极的上部块体均为绘图占位。** 佛殿地面来源角色仍是 `published_site_box`，只表示刊图中的佛殿基址框；太极地面仍是 `scale_template`，只表达报告尺寸的近似尺度片。上方块体没有把这两类来源升级为已知建筑轮廓，也没有确认殿身、柱网、层数或屋顶。阊阖门、塔座和寺南门的地面来源角色亦保持原样；它们的上部块体同样不构成新增考古成果。

| 文件 | 用途与限制 |
| --- | --- |
| `research/panorama-r12/massing-overview-clean.svg` / `.png` | 同一共同画幅的无文字计层占位输入；PNG 以 2 倍分辨率输出，地面 H 不变 |
| `research/panorama-r12/massing-yongning-clean.svg` / `.png` | 同组占位的局部显示放大，供图像编辑读取结构 |
| `research/panorama-r12/massing-yongning-counted.svg` / `.png` | 带楼层标号与可见限制说明的审看版，明确“高度、收分及屋顶均为绘图参数，非考古立面复原” |
| `research/panorama-r12/massing-display-parameters.json` | 主要绘图参数、显示变换、原地面来源角色及输入／输出 hash；完整算法以其中锁定 hash 的生成代码为准 |

在与第 6 节相同的固定环境运行 `python tools/panorama_r12_massing.py` 可复算这些文件。输入登记包含实际读取的 `projection.json`、`projection-clean.svg`、生成脚本、旧层数审查及原投影引用的输入。登记这些 hash 是为了追溯绘图过程，不增加史料精度。

第三次图像生成已经使用的旧版计层 PNG、SVG、参数 JSON、生成脚本及全景占位图，按原字节留存于 `research/panorama-r12/generation-inputs/attempt3-*`。`attempt3-input-manifest.json` 记录当次实际三幅输入的顺序、归档路径和 hash；旧参数保留原貌，不用后来补齐的说明替换历史输入。归档仅证明当次输入身份，不表示该次生成图已经通过审查。
