# V14 试绘审查与共同平面依据

研究版本为 **R12.1**，实现版本为 `panorama-review-v14`。本轮把 R11.1 共同坐标平面作为布局约束，先生成可复算的透视底稿，再审看实际全景中的变化。首页继续使用已批准的 V12；V14 图像是否达到候选要求，由绑定该张实际 PNG 的成图审查决定。发布审查页不改变图像的审查结论或首页批准状态。

## 图像状态与页面发布

本页既能呈现通过所列检查、可供用户审看的候选，也能公开未通过试绘的依据和偏差。两者使用不同的状态链，不能互相替代。

| 图像状态 | 成图审查状态 | 页面与首页入口 | 发布条件 |
| --- | --- | --- | --- |
| `candidate_for_review` | `accepted_for_user_review` 或 `accepted_for_user_review_with_known_limits` | 标明候选图、待审看 | 成图审查没有未解决的阻断项，技术门禁通过；首页替换仍未获批准 |
| `needs_revision` | `rejected_needs_revision` | 标明“V14试绘审查·未通过” | 完整公开主审与独立审查的全部阻断项，技术门禁通过；不称为已完成空间校正的成果或可替换首页的候选 |

图像状态、审查状态和阻断项在原始记录、发布记录、清单、`build-info.json`、`release.json`、页面及两个首页入口中保持一致。未通过状态必须在主图之前显著显示，切换图像、并排对照和禁用 JavaScript 均不隐去该状态。技术验收的 `passed` 只表示页面、文件和状态链符合交付合同；它不会把试绘失败改成视觉通过。

当前交付采用哪条状态链，以 `research/panorama-r12/image-record.json` 及其绑定的实际审查为准。`panorama-candidate-v14` 是沿用的图像标识，文件名中的 `candidate` 不构成通过认定。

## 读图入口

`luoyang-panorama-v14.html` 提供 V14、V13 二修和 V12 的完整原幅。URL 参数 `view=v14|v13r2|v12|compare` 恢复阅读模式；并排模式显示 V14 与 V13 二修，窄屏顺序排列。无 JavaScript 时三幅图、底稿、逐项依据和下载均能阅读。

页面把三类信息分别说明：

- **原图内部比例**：同源门址、塔座、佛殿及墙段之间的几何关系。
- **艺术构图位置**：共同工作平面如何投到画面，以及上部建筑的艺术表达。
- **待核的外部落位**：局部图接入全城仍为候选绑定，不能当作实地注册。

透视底稿不经过图像生成。整幅布局、永宁寺局部、投影数据和方法说明按原字节提供，页面不重新绘制底稿。实际候选使用内置图像工具，原始 PNG、网页 WebP、等比例手机版、完整提示词和成图审查分别登记。

## 输入与身份

源记录为 `research/panorama-r12/image-record.json`，schema 为 `luoyang-panorama-v14-image-v1`。`source_image` 绑定前版 V13 二修的全幅 WebP；`source_png` 记录本张新候选原始 PNG 的路径、尺寸与 SHA256。`full`、`small` 绑定实际网页图像；小图只允许保持原幅比例。

`conversion` 使用 `luoyang-panorama-webp-conversion-v1`：Pillow 11.2.1、libwebp 1.5.0，从同一不透明原始 PNG 转 RGB；全幅保留原尺寸，手机版直接从原 PNG 以 Lanczos 缩至 960 像素宽、高度为 `round(原高 × 960 / 原宽)`。两幅均以 WebP quality 92、method 6、lossless false、exact false 编码，显式去除 EXIF／ICC／XMP，不裁切。验证器重新生成两份字节并逐字节比较，因此另一轮同尺寸图或同尺寸移位裁图不能凭各自有效哈希混入。

每项 `changes` 同时保存：对象、实际成图观察、空间依据、画面处理、尚不能确定的部分与回查链接。`treatment_type` 区分本轮改变、沿用并复核及仍未定位。已有的三层南门、九层木塔和寺墙从属不能自动重复计为本轮新增成果；是否保持，应以实际新图审查为准。

`supporting_assets` 按角色列出底稿、投影 JSON、逐项证据表和方法文件。投影输入必须保存可复核的源文件 SHA256，保持 `field_registration_verified=false` 和 `new_ancient_coordinates=0`。几何投影的一致性不意味着生成图逐像素遵循底稿；实际匹配、偏离和残余问题须写入成图审查。

`candidate-review.json` 必须绑定同一原始 PNG，并与图像记录的状态一致。对于 `candidate_for_review`，审查必须通过且不残留阻断项；对于 `needs_revision`，审查必须明确为 `rejected_needs_revision`，并保留非空、逐项可读的实际阻断问题。通过含义限于已列检查项，不是整座城市的历史真实性认证；公开未通过试绘则是保存失败原因，不表示这些问题已经修复。

若提供独立 `visual_audit_file`，同样检查其 PNG 哈希、与主审一致的审查状态和 `homepage_replacement_approved=false`。未通过试绘的发布记录与可见页面须保留主审、独立审查阻断项的有序并集，不得漏掉任一审查提出的问题；通过候选的两份审查都不能残留阻断项。保存该 JSON 的文件哈希不能代替这些身份与状态检查。

历次试绘审查以独立 JSON 保留，每轮记录自己的图像身份、实际观察与结论。新一轮成图不能覆盖前一轮审查，当前主图也不能继续挂接前一张 PNG 的审查。页面按实际登记的试绘审查生成历史列表，未通过的试改在对照表与详细依据中显示“已试改，未通过”。

本轮共六次真实试绘，均未获接纳；`total_attempts=6`、`displayed_attempt=5`、`latest_attempt=6` 分别表示总次数、主显示样张和最新试绘。主图、两个 WebP 派生图、发布用成图审查和偏差图继续绑定第五次 PNG。第六次南门仍只可辨两层，门基与寺南墙没有服从共同底稿，塔门独立基脚仍未核明；其原始 PNG、实际提示词和独立审查作为明确标注“未通过”的可下载附录保留，不拿第五次观察代替第六次结论，也不将第六次冒充新的通过候选。

### 第五次图面偏差的比较口径

门槛约y477与底稿框心y451不是同名控制点；采用同侧来源南缘约y452.4—453.3作画面参照时，约前移24像素。佛殿可见前基约y426与同侧来源前缘约y416—417相比，约差9—10像素，不能把与框心y414相减的12像素称为精确位移。人工约读通常有约5—10像素读数不确定性，且受到遮挡、台基高度和边缘辨识影响；塔脚附近的可见边也不自动等于来源塔座的接地边。原始第五次独立审查和偏差图按原字节保留，发布记录的 `measurement_notice` 及可见正文补明上述口径，不重写原件或将画面差值称为考古误差。此澄清不改变未通过结论。

## 发表与旧版保护

构建在 R11 完成后执行 `tools/panorama_v14.py`，发布目录为 `panorama-v14/`，build-info 键为 `panorama_review_v14`。两首页只在原有 R11 入口之后增加一个精确、唯一、可逆的新审查链接；链接文案随实际图像状态变化，未通过试绘的入口直接标明“未通过”。

R11 全城平面、全部旧专题、V13 二修、V12 批准图与相关依据均保持同一构建内原字节。进入 R12 前的 `release.json` 和两个首页完整保存。验证先校验 R12 的新增清单、文件、release 变化和首页插入，再向旧版验证器暴露准确的 R11 库存及旧字节；旧证据断言不放宽。

新的语义检查覆盖图片身份、禁止自行批准、禁止手机裁图、底稿来源变化、完整阻断项与状态一致性、旧资源保护、真实跨页锚点和前驱恢复。桌面及手机浏览器分别检查三图切换、键盘对照、URL 恢复、底稿加载、来源跳转、无脚本阅读，以及每个下载链接的一次实际点击与实际文件 SHA256。未通过试绘还需检查主图前完整阻断项、图注、切换按钮、下载标签和试绘历史可见。下载原件、报告和截图保存为验收证据。原有浏览器检查继续执行，工作流预算不因本页改动而放宽。

## 研究限制

目标时段继续为 516—528 年综合研究窗口。没有新增古代实测坐标、古岸几何或证据等级提升。外郭相关遗存范围不等于连续城墙，片区窗口不等于坊界，候选点不等于建筑占地。2013 宫城概览中的调查点、版筑范围与未分期图线不能直接变成确定的地面建筑。未知院界、北门、回廊和普通房基继续依各自证据处理。

本说明记录实现合同。是否正式上线，以相应提交的 `build → deploy → verify-live`、公开资源回读及 Issue #52 的交接为准；是否替换首页，以用户对具体候选图的审看决定为准。
