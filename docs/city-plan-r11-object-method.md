# R11：共同母图中的对象、方向与未定位名录

## 交付性质

R11 将源图几何、刊载构件和可审查的文献候选点接到同一个绘图框架。对象模块新增的几何全部是 `Point`，没有按寺名、官署名、里名生成院墙、坊墙、塔、殿或道路。共同母图采用 `prosperity_maps.PROJECTION` 的来源图局部米制坐标：x 向东，y 向北。此坐标框架提供共同阅读基底，并不使文献候选点成为测得的古址坐标。

目标时层仍为 516—528 年河阴事件前的盛时综合。它不是一幅已经证明所有对象在某一年同时存在的测绘图。339 条目录记录也不是 339 座建筑；其中包括道路、河山参照、寺院、坊里、宅第、官署、构件、前代旧址、后出名称、制度与志怪叙述。

本轮新增输入在 `research/city-plan-r11/objects.json`，构建器是 `tools/city_plan_r11_objects.py`。`build_objects(root, geometry)` 只读取输入，返回 `frame`、`objects`、`features`、`entities`、`constraints`、`diagnostics`、`regions`、`sources`；不改源几何，也不写回旧目录或旧图。

## 对象身份与证据归属

R10 的 321 个节点保留完整映射，原 259 条关系逐条保留。其中 164 条是单轴方向，其余为所属、同源、顺序、邻近、未知连接和身份候选。

`entity_id` 是目录及证据归属，不是几何唯一身份。例如永宁寺、九层塔和塔北佛殿都引 `ic_yongning`，但必须分别保存为寺主体、塔构件、殿构件。平等寺的 527 年叙事、532 年造塔和毕功年候选也是不同事件，不转换为三个址点。景明三池的数量记述、七层塔和立寺事件不合并成一座建筑或一个池岸。

本模块以 `object_id`／`component_id` 识别绘图对象，以 `entity_ids` 保留原目录连接。少数宅寺前后身份沿 R10 已有判断共享地点签，并不主张前后足迹完全重合。原 339 个 ID、名称、原文、出处和时相记录全部保留，源对象、候选点和未定位对象都能回查。

永宁寺主体同时保存06a残墙及新刊候选院墙以供回查，但方向评价的 `evaluation_feature_ids` **只取新刊7段墙**，`evaluation_proxy` 为 `published_plan_wall_envelope_only`。06a残墙是独立对照源，不并入一个联合院界，也不参与该方向proxy；新刊7段墙的包络仍只是候选刊图边界。寺主体不另造院心；塔基符和刊载塔座属于同一塔构件的两种表达，不增加第二座塔。佛殿绑定新取得的刊载基址框。门、院墙和塔殿也不互相借用几何中心。

## 旧文献图到母图的工作配准

旧图是 12000×11000 的文献绘图坐标，本轮只使用其中适合的图签作候选初始化。公开的最小二乘仿射变换使用九个名称可核对的门点：宫城阊阖门、千秋门、建春门、大夏门、广莫门、西阳门、东阳门、青阳门、西明门。

以下不作为配准对应：

- 旧永宁全寺图签与源图塔基符不是同一物理对象。
- 旧金墉情境框中心与金墉丙城参考符不是同一测点。
- 宣阳门没有已绑定源图 Point，不补造控制点。

矩阵、每一对旧图签／来源点、拟合位置和逐点残差都在 `diagnostics.registration` 中公开。这是两个表达系统之间的工作配准；独立测量控制点数量仍为零。仿射只作用于候选点，不作用于源图线迹、刊载平面或任何定尺构件。

当前九门拟合的绘图均方根差约 **259.59 母图米**，最大差约 **461.80 母图米**。这两个数值是旧图布局差，**不是考古测量误差、定位精度、置信区间或历史位置的误差半径**。母图采用米制框架，不表示已将古籍里、步换算成现代米。

旧 `area` 的矩形、`pool` 的椭圆、`compound` 的通用院式、道路宽度和完整长线全部不导入。旧道路只能提供明确注明的“候选道段参照签”，不能恢复端点或连续街线。普通旧 group 中心不作为成员位置；经审定的共同方向群另作集体阅读签。

## 哪些对象可以得到候选点

一个普通文献对象必须已有独立方向关系或已核门内外大方向，而且能通过现有关系链接到源对象，才进入候选求解。仅有寺名、里属、同源、同段列名、时间或制度关系，不能激活一个坐标。

若两个对象都已有独立方向，明确的容纳关系可以把该局部方向群接入上一级广域情境。例如八角井另有凉风观在其北的方向，井又明确在凌云台上；此容纳边可以接续台、园关系链。但里内普通宅名、建阳里其余寺名、劝学里三寺、河间王宅的无方位构件仍没有独立址点。到源对象的路径若含这种容纳情境，逐对象标出 `context_only_edges`，不能将其称为定位控制。

完全孤立的局部方向群保留在未定位名录。典型包括柰林—都堂群、尚无共同控制的坊内街路和南部礼制遗址局部关系。长河、山域、张方沟及只有区间作用的圜丘也不由一个点替代整个对象。1997／1999 底图的现代洛水仍不绑定成北魏洛水。

部分对象只有共同道侧或市侧而无内部次序，因此使用共同方向签：建春门内三署、大市同侧各两里、洛南四馆和四里。每个成员保留自己的对象记录、原文和约束；成员 `geometry` 为空，群签标记 `not_individual_locations=true`。它不表示成员同址、彼此相邻、等大、同纬或南北街列。

## 方向求解与未满足项

东西、南北只约束对应单轴。东／西不约束 y，南／北不约束 x；没有距离、等距、共同中轴、共墙或同一街路的推论。R10 其余关系均不进入方向求解。校补、回指、同体条件仍随原关系保存，不因数值相容而提高证据等级。

初始化优先使用可审查的旧图签仿射结果；没有适合旧签而已有方向连接的对象，可以从已接入对象传播一个公开的绘图种子。传播时选择的自由轴、所用参照包络和 110 米显示步长都逐条保存。110 只是初始化参数，不是史料距离。

求解使用可重复的单轴不等式投影。24 米显示间隔只是便于阅读的参数，不是建筑退距或考古量距。源几何及其固定 proxy 不移动；双方固定而有冲突时保留未满足结果。每个候选点保存初始坐标、最终坐标、调整向量、调整长度、约束轴及自由轴。标签避让不能回写这些坐标。

其中三条旧“门内御道”参照曾共用跨门长线的中点，工作配准后落在门外。按门内大方向校正参照签的位移约 0.90—1.02 千米；这一较大的显示调整逐对象公开。它不移动源道迹，也不证明一条古街移动了同样距离。

全寺等非点对象只用公开列明的单一评价几何包络评估方向。永宁仅使用新刊7段墙；06a残墙仍可叠加对读，不能因两源都挂在寺名下就将其联合包络当院界。新刊包络不是完整寺界，两个来源的位置差异继续独立保留。`constraints.numeric_evaluation` 给出实际使用的轴范围、signed separation、显示间隔和是否使用共同群签。状态分为满足、未满足、不可评价、非坐标关系等。不可评价的原关系继续存在，不当作已被图面验证。

## 时相和构件控制

七个后出寺名在主层沿用此前宅名。城内建中与城东建中不因同名合并；归觉转换保留永安 528—530 的时段条件；高阳王、城阳王、东平王、河间王等宅寺转换各保留本来的证据强弱。

平等寺 532 年始造的五层塔、大觉寺永熙砖塔不能进入盛时既成构件。景明和冲觉的塔分别保留始造／工程与完工未证，不拿寺院存在证明塔已完成。事件、记名层、纯制度对象不生成新几何。未知时相使用明确的 `unknown` 或空列表，避免把程序空值印成历史阶段。

## 覆盖表和十一片区

339 条实体均输出原 `id`、`name`、主层名、`object_ids`、`component_ids`、`feature_ids`、`placement_class`、`unplaced_reason`、原文及出处。所属信息按可唯一核对的名称或 ID 补入名录连接；这些补充明确 `used_by_solver=false`，不让纯成员获得虚点。无法唯一解析的所属保留原目标词和候选列表，不默选同名对象。

十一片区均用同一母图框架的 `bbox` 裁看。视窗范围不构成历史区界、坊墙或遗址边界。未定位成员随所属片区可查，但不会因进入区域列表而得到坐标。每项 `source_refs` 提供仓库路径、JSON Pointer、输入 SHA；目录还保留原 `source_url` 和 `source_ref`。

构建后应以本次实际 `diagnostics` 统计为准，不能把对象数、图元数、约束数与建筑数量混用。本轮对象模块没有新增建筑足迹，只有源／刊载几何绑定和文献候选阅读点。

## 构建与定向核查

```bash
/tmp/r11-venv/bin/python tools/city_plan_r11_objects.py --output /tmp/r11-objects.json
```

本模块构建时检查 339 原 ID 完整性、R10 的 321 节点及 164 方向基线、候选几何只能为 Point、坐标有限性和配准门点身份。网站端另核视觉布局、筛选、深链接、下载和公开源数据。数据相容性检查不能替代历史证据复核。
