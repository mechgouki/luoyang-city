# 盛时洛阳 P4.5.1：来源图与建筑类型可追溯分布第一批

**研究时层：**北魏盛时516—528年文献综合层，非考古单年快照。
**技术目标：**将已经发布的P1城市来源图、P1建筑表列尺寸、P4.4建筑类型关联为一个可审查的实际空间结果，**不**另造古址经纬度、完整坊格或古建筑立面。

## 已核对的全部几何对象结构

在 `research/prosperity-v1/geographic-evidence.json` 里有**30**项既有图示几何，来源2012年申遗保护管理图06a（底图1997航摄、1999测量），其标注西安1980图格；这批几何里**13项**链接现有实体ID。结构并非30座完整单体建筑：

- 26项为多期遗址遗存的图示点、墙线与道路残段，某些标记仅是取图符中心。
- 1项由三面宫墙**推断补齐北边线**的布局显示范围，不可称已有完整实测宫墙。
- 1项外郭相关遗存范围，不是全部坊墙连续落点。
- 1项1997/1999近现代洛水图示线。
- 1项邙山来源图地理文字标签。

通过原SVG已有点位的几何属性重用，不以已批准首页全景反推具体寺院位置，不将现代洛水线路赋给北魏城。

### 必须单独对待的宫院线

- P1 `geo-yongning-temple-walls` 为局部围墙多折线。与P1 M04的表列301×212m不完全相符，绝不强制补南北两墙做真实院墙多边形。
- P4.3太极殿宫院310、370、380m报告尺度的原始端点不明；仍不可从某一个尺寸猜宫墙。
- 2017太极殿东北角院址报告发现东界/北界，但整幅可量读图与共用位置控制点尚缺，不能自动叠加到P1来源图的宫墙线。

## 未在P1图中独立定位的P4.4四类门制

`palace_side_gate`（神虎门实例）、`east_ge_gate`（主殿与东堂之间的东閤门）、`roofed_court_gate`（东堂北屋宇式院门）、`corridor_court_gate`（院廊隔墙式门）。

这些类型有考古局部结构、柱础或文字关系依据，但P1 30项几何没有与这些对象完成独立图上同控制点绑定。即使知道某处“在东堂北”，仍不能认为它已取得已证实的全城WGS84点址。故这四类只放在并列表和非空间图册，不绘假定位点。

## 本批新增图像与可操作网页

1. `grounded-distribution.svg`：在P1城市来源图原SVG**原样保留**的30项几何上，覆盖已有的四处代表点（仅从SVG复用其cx/cy），图上编号可按不同建筑交互高亮；不是新考古测量。
2. `scale-plates.svg`：C01—C04四个独立的台基尺寸卡，统一3.2 px/m。只比较平面发表约值，*不共享*古址中心、道路原点或朝向标定；原建春门东西/南北比例较狭长是报告值，不据此复制别的城门。
3. `evidence-tiers.svg`：在同一视图中对比“四处已有旧来源图代表点”和“四类只有类型/局部关系的门制”，另保留市场／民居／学校等分类证据不承诺实测人口密度。
4. `prosperity-city-distribution.html`：可点选四处来源图标记与对应卡片，深链接 `?focus=C01..C04` 支持刷新；有PDF、SVG、CSV、JSON及可校验ZIP。入口位于首页研究部分，已批准的H2高清画面和手机资源字节完全不变。

## 可重复运行和证据等级

P4.5.1的生成器从原P1 `prosperity/source-layout.svg` 中查找已有`data-feature-id`的元素，直接读取原`cx/cy`，避免新增另一套投影计算造成虚假偏移。所有新布局图中的像素坐标只代表当前SVG显示位置，不是古代实测坐标。源头元数据、P4.4类型、P1 M02/M03/M05尺寸和M04院界按字段逐项校验，不手抄独立常量来假装多个来源独立证实同一观点。

现有source地理数据CRS `EPSG:4610`表示来源图已登记的西安1980地理框架，不等于实现了独立现场控制转换；H2的视觉图片不是空间证据。

- 有真实新尺寸／新分期证据后再更新模型，不擅自重绘已批准的全景，只有新候选的审美选择才需请用户决定。
